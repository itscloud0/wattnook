## Charge control: observed on this Mac

- macOS 27.0.1, build 26A434. Existing daemon reports unsupported charge control; its saved 80% limit is not active enforcement.
- One-shot read-only gosmc KeyInfo probe: CH0B, CH0C and CHTE have DataSize 0; bfF0, bfD0 and bfE0 return IOKit 0xe00002c1 (not privileged). No raw reads, writes or adapter toggles were attempted by this probe.
- PowerUI's smart-charge client is available, with advertised limits 80, 85, 90, 95 and 100. Initial state: configured 100, enabled false.
- User explicitly approved enabling Apple's 80% limit. A narrow native helper validated method ABI, called setMCLLimit:error: once with 80, then read back 80/enabled. A separate read-only process also returned 80/enabled with no error.
- This verifies configuration, not physical charge-stop behavior. `pmset -g battlimit` still prints "No battery level limits set"; do not use that getter as confirmation of this PowerUI setting. Observe actual behavior separately. Apple documents occasional charging to 100% for state-of-charge estimation, so native limiting is not an unconditional hard ceiling.
- No WattNook daemon/helper/source behavior, adapter settings, Keep Awake, SIP or entitlements were changed. Custom 33/30°C heat protection remains unavailable; Apple's own thermal management is not that feature.

### Likely product fix, not implemented

Add an explicitly selected native-limit backend instead of making adapter toggling an automatic fallback. Query available values, read the actual system setting, validate requested values and report unsupported features. The existing slider/config must distinguish a saved preference from an enforced native setting. Native PowerUI is a private framework: use runtime/ABI checks and bounded error handling; future macOS updates can break it. Preserve older firmware backends. Test mode selection, allowed limits, failure/unavailable states and UI capabilities before privileged installation.

Do not implement custom thermal pause by repeatedly cutting wall power. Do not disable SIP or attempt to forge Apple-private entitlements. Native limiting does not restore arbitrary sub-80 limits or direct charge inhibition.

### Independent cleanup direction for WattNook

Start with user-triggered scanning, grouped results and a review step, not automatic deletion or an always-running scanner. Build independent rules for a small documented set of cache/log candidates; show path, size and explanation, skip running apps and inaccessible areas, and keep candidates unselected until reviewed. File presence alone does not make it junk.

Use a dedicated Cleanup view, not more rows squeezed into the battery popover. Keep the menu-bar app lightweight: cancelable worker, bounded results, no persistent scan when disabled. Use Trash where appropriate and state recovery limits; never present removal as universally safe. Guard containment, symlinks and changed files before any approved operation.

Exclude swap/VM, APFS snapshots, backups, Photos/mail databases, document versions, browser profiles, AI models and OrbStack/Docker disk images from initial removal rules. Large files and developer data may be shown separately for manual investigation, never classified as disposable solely by size or age.
